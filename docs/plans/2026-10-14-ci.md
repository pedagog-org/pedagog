# CI

**Date:** 2026-10-14
**Status:** Planned

## Rationale

There is no CI. clippy runs only in the local pre-commit hook (which can be skipped with
`--no-verify`), and tests run only when someone remembers. Since design-doc-v2 the corpus
tests fail without the `recipes/` submodule, so a missing or broken checkout would also go
unnoticed. A small GitHub Actions workflow keeps `main` and every PR green.

## Decisions

- **Toolchain pinned** to `1.97.1` in `rust-toolchain.toml` (currently unpinned → floating
  stable). Local and CI use the same compiler and clippy; upgrades are a deliberate PR.
- **Format once, then enforce:** one `cargo fmt` commit for the whole workspace (121 diffs
  today), listed in `.git-blame-ignore-revs` so `git blame` skips it; then `cargo fmt
  --check` in CI and in the pre-commit hook.
- **Runner:** `ubuntu-latest` (x86_64). The code and tests don't depend on the architecture;
  arm64 runners can come later if CI builds images.
- **Cache:** `Swatinem/rust-cache@v2`, keyed on `Cargo.lock` and the toolchain.
- **Submodule:** `actions/checkout` with `submodules: true`. Both repos are public, so no
  token is needed.

## Workflow

`.github/workflows/ci.yml`:

- Triggers: `pull_request`, and `push` to `main`.
- `concurrency` group per ref with `cancel-in-progress: true`, so a new push to a PR
  cancels the older run.
- One job, steps in order (fail fast on the cheapest check):
  1. `actions/checkout@v4` (`submodules: true`)
  2. `rustup show` — installs the pinned toolchain and the components listed in
     `rust-toolchain.toml`
  3. `Swatinem/rust-cache@v2`
  4. `cargo fmt --check`
  5. `cargo clippy --workspace --all-targets -- -D warnings`
  6. `cargo test --workspace`

## Alternatives considered

- **Float on stable** — rejected; a new clippy lint could fail CI with no code change.
- **No cache** — rejected; every run would rebuild all dependencies from scratch.
- **Skip rustfmt** — rejected in favor of a one-time reformat plus enforcement.
- **arm64 runner** — deferred until CI builds images for the Pi/RK1 nodes.
- **`dtolnay/rust-toolchain` action** — not needed; the runner's rustup reads
  `rust-toolchain.toml` itself.
- **Pinning actions by commit SHA** — stronger supply-chain hygiene, but harder to read and
  update. Major-version tags (`@v4`, `@v2`) for now; see open questions.

## Open questions

- **Branch protection:** require the CI check before merging to `main`? This is a GitHub
  repo setting, done by you after the first green run.
- **Action pinning:** move to commit-SHA pins (perhaps with Dependabot for updates) later?

## Rollback

Delete `.github/workflows/ci.yml` and revert the hook and toolchain changes. The format
commit is behavior-neutral; it can stay, or be reverted, in which case remove its entry
from `.git-blame-ignore-revs`.

## Implementation steps

Branch `chore/ci`, one commit per step:

1. `rust-toolchain.toml`: add `channel = "1.97.1"`.
2. `cargo fmt` across the workspace; confirm clippy and tests still pass.
3. `.git-blame-ignore-revs` containing the step 2 commit, with a comment; note in the README
   that `git config blame.ignoreRevsFile .git-blame-ignore-revs` enables it locally (GitHub
   applies it automatically).
4. `.githooks/pre-commit`: run `cargo fmt --check` before clippy.
5. `.github/workflows/ci.yml` as above.
6. README "Development": mention CI and the fmt check.
7. Open the PR; confirm the workflow runs green on it.

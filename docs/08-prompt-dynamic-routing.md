# 08 — Prompt: Dynamic Path Routing via the Orchestrator

> **Date:** 2026-06-21
> **Status:** Prompt captured; design under discussion (see `08-design-dynamic-routing.md`, Draft).
> Builds on the M1.5 path-routing spike in [`07-design-first-steps.md`](./07-design-first-steps.md)
> and the routing architecture in [`02-design-exam-system.md`](./02-design-exam-system.md).

## Goal

Make the **dynamic `/s/<id>/` path routing work with the correct orchestrator** — i.e. move from
the M1.5 throwaway, which used a **static Traefik file-provider config with one hard-coded
`/s/test` route** (`deploy/spike-path-routing/`), to **per-session routes that appear and disappear
dynamically** as sessions are created and torn down, driven by **Nomad**.

"The correct orchestrator" = **Nomad** (per doc 02: scheduling, placement, health, reschedule).
Doc 02 already anticipates this — §9's scaling diagram labels the Traefik→pool edge
**"path routes via Nomad service discovery,"** and §7.5 notes "routing follows via Nomad service
discovery." This step turns that into a concrete, agreed design.

## Decisions (2026-06-21)

- **Scope of this step:** **Design first, no code.** Write the prompt + design docs describing the
  Nomad jobspec + Traefik routing approach; **no configs/jobspecs are written until the design is
  approved.** (A runnable spike — call it M1.6 — would follow as a separate, explicitly-approved
  step.)
- **Service registry / discovery mechanism:** **Nomad native service discovery** (Nomad 1.3+
  built-in registry), consumed by **Traefik's `nomad` provider**. **No Consul** — keeps to the
  "few, well-maintained dependencies" rule and avoids adopting a service-mesh component we don't
  otherwise need. (Consul catalog was considered and declined for v1.)

## Constraints carried from prior docs

- **Path-based routing** (`/s/<id>/`), Traefik edge, WebSocket on the same route (M1.5: PASS;
  code-server emits relative asset paths, so `stripPrefix` works).
- **Per-session jobs are parameterized batch/dispatch jobs** (doc 03): a clean exit completes the
  alloc; no restart on success.
- **The control plane owns the routing decision** (doc 02 §5.1, §9) — it must remain the thing that
  decides which path maps to which session, even if Nomad+Traefik do the discovery/plumbing.
- **`session_id` is a secret capability token held only by the daemon, never readable by the
  student** (doc 02 §4.2, follow-up #2). The browser-visible URL path therefore **cannot** be the
  `session_id` — a point the design must address.
- Rootless Podman via `nomad-driver-podman`; Wolfi base; multi-arch (arm64) targets.

## Decisions & clarifications (follow-up, 2026-06-21)

Terminology change + a control-channel clarification:

- **`session_id` is NOT a secret.** It is a public, stable, opaque session identifier. It may
  appear in the **URL/route** (`/s/<session_id>/`), in Nomad service tags, on the dashboard, and in
  logs. The separate `route_id` proposed in the draft design is therefore **dropped** — we route on
  `session_id` directly.
- **The secret is the session's *container token*.** This is the high-entropy capability credential
  (the thing doc 02/03 had been *calling* `session_id`). It is generated by the CP, injected only
  into that session's daemon (Nomad `meta` → `template` → tmpfs, `0400 pedagog`), held by **only the
  CP and that one daemon**, and **never** appears in a URL, tag, or log.
- **The container token authenticates the CP↔container control channel in both directions.**
  Because it is a shared secret known to exactly the CP and that session's daemon, the CP can use it
  to reach **into** the container to **`EndSession` (kill)** or **`UpdateDeadline` (send updates)**,
  and the daemon uses it to authenticate its **outbound** heartbeat/submit/archive calls. This
  upgrades doc 03's planned control endpoint from **nftables-only** to **nftables + token auth**
  (defense in depth); pair with TLS on the private net so the bearer token isn't sniffable.
- **Reconciliation needed:** docs 02 and 03 currently use `session_id` to mean the secret. They must
  be updated to the new split (`session_id` = public/routable; `container token` = secret).
